# Checkpoint GLB-018: Jadwal dan kalender mingguan

Task: [GLB-018](https://app.clickup.com/t/86eyvadw3) · Jadwal 8-9 Oktober 2026 (dimulai 6 Okt) · Kebutuhan: FR-SCHEDULE-001, BR-003, BR-PEND-006, SRS §5-§7 (`GET/POST /api/schedules`, `PATCH/DELETE /api/schedules/{id}`)

## Acceptance criteria (ClickUp)

1. Buat/ubah/jeda/aktifkan/hapus jadwal mendatang untuk pemeriksaan, obat, insulin dan lainnya berjalan.
2. Nama obat/dosis berupa input bebas; WIB/WITA/WIT konsisten; recurrence dan tombol selesai tetap off sampai keputusan final.

## Temuan analisis (6 Oktober 2026)

- Tabel `schedules` dan `schedule_occurrences` sudah ada sejak Sprint 1, belum dipakai. Pengguna hanya punya hak `select`; RLS `schedules_owner_all` hanya untuk akun `active`.
- **`schedules` tidak punya kolom tanggal**, hanya `local_time`. FRD mewajibkan input tanggal + jam. Tanpa pengulangan (BR-PEND-006), setiap jadwal adalah satu kejadian pada satu tanggal.
- `export_my_data` sudah mengekspor `schedules`, tetapi tanpa tanggal/waktu jatuh tempo.
- Bottom bar mobile berisi 5 item; Laporan dipakai jauh lebih jarang daripada jadwal.

## Keputusan desain

| Topik | Keputusan | Alasan |
|---|---|---|
| Model | Kolom baru `schedules.local_date`. Satu jadwal = satu kejadian; satu baris `schedule_occurrences` (`due_at` UTC, `pending`) dibuat/diubah oleh RPC yang sama. | Recurrence off. GLB-019 (dispatcher) cukup membaca occurrence yang jatuh tempo. |
| Zona | Jadwal disimpan dengan zona profil saat dibuat/diubah; tampilan selalu menulis zonanya (mis. "07.30 WIB"). | AC: WIB/WITA/WIT konsisten. |
| Mendatang saja | Buat/ubah wajib jatuh tempo > sekarang dan ≤ 366 hari ke depan. Ubah, jeda, aktifkan, hapus hanya untuk jadwal yang belum lewat. Jadwal lewat tampil "Sudah lewat", hanya baca. | FRD: perubahan tidak mengubah kejadian yang sudah terjadi. |
| Jeda | `active = false`; occurrence tetap `pending` dan GLB-019 tidak membuat pengingat untuk jadwal tidak aktif. | FR-REMINDER-001: jadwal dijeda tidak menghasilkan pekerjaan. |
| Hapus | Hapus permanen jadwal mendatang (cascade occurrence). | Data milik pengguna, belum pernah terjadi. |
| Obat/dosis | `medicine_name` (≤120) dan `dose_note` (≤200) input bebas, hanya untuk kategori obat dan insulin; kategori lain disimpan null. Tanpa katalog atau saran dosis (BR-OOS-001). | AC. |
| Selesai & pengulangan | Tidak ada tombol "Sudah dilakukan" dan tidak ada pilihan ulang mingguan. `recurrence_rule` tetap null (constraint lama). | BR-PEND-006. |
| Akses tulis | 4 RPC `security definer` (`create_schedule` dengan idempotency key, `update_schedule`, `set_schedule_active`, `delete_schedule`), memeriksa `user_can_access_health()` dan pemilik. Batas 200 jadwal mendatang per akun, rate limit 30/menit. | Pola sama dengan catatan gula darah. |
| Baca | `GET /api/schedules?week=YYYY-MM-DD` (Senin) mengembalikan jadwal dengan `local_date` dalam minggu itu, lewat RLS biasa. | Kalender mingguan sederhana. |
| UI | Halaman `/schedule`: navigasi minggu (sebelumnya / minggu ini / berikutnya), 7 hari Senin-Minggu, tiap jadwal menampilkan jam + zona, kategori, nama, obat/dosis, status. Tambah/ubah lewat dialog. | FRD: kalender mingguan tampilan sederhana. |
| Navigasi | Bottom bar mobile: Ringkasan · Riwayat · (+) · **Jadwal** · Profil. Laporan dipindah ke tombol di Ringkasan dan Riwayat; menu desktop mendapat "Jadwal". | Keputusan pengguna 6 Okt 2026. |

## Dampak ke aplikasi

- **Database**: 1 migration (kolom `local_date`, 4 RPC, `export_my_data` menyertakan `localDate`/`dueAt`). Production: `db push` oleh pengguna.
- **API**: `src/app/api/schedules/route.ts`, `src/app/api/schedules/[id]/route.ts`; validasi di `src/lib/domain/schedule.ts`.
- **UI**: halaman `/schedule`, komponen `ScheduleForm`/`WeekCalendar`, Shell (nav), tombol Laporan di Ringkasan dan Riwayat.
- **Belum termasuk**: pengingat (GLB-019/020), kartu jadwal di dashboard (GLB-020).
