# Checkpoint GLB-023: Ekspor data portabel

Task: [GLB-023](https://app.clickup.com/t/86eyvadxq) · Jadwal 2-5 Oktober 2026 · Kebutuhan: FR-EXPORT-001, SRS §6 (`POST /api/account/export`), §10, §11

## Acceptance criteria (ClickUp)

1. Ekspor data milik sendiri tersedia sebagai JSON, dengan re-authentication dan unduhan privat terbatas waktu.
2. Ekspor tersedia selama grace period penghapusan; akses lintas pengguna ditolak; file kedaluwarsa dibersihkan.

## Temuan analisis (1 Oktober 2026)

- Tabel `data_exports` (state `queued/processing/ready/failed/expired`) sudah ada sejak Sprint 1, belum dipakai. Pengguna hanya punya hak `select`.
- **RLS data kesehatan hanya untuk akun `active`** (`user_can_access_health()`), padahal FRD mewajibkan ekspor selama `deletion_pending`. Query biasa dari server sebagai pengguna akan mengembalikan kosong saat grace period. Maka ekspor memakai satu RPC `security definer` yang memeriksa `user_can_access_limited_account()` (active atau deletion_pending).
- **Tidak ada object storage** di stack self-host (Supabase Storage tidak dipasang, ADR-0001). SRS mengasumsikan file + signed URL.
- Akun Google tidak punya password, jadi re-authentication tidak bisa selalu berupa password.

## Keputusan desain

| Topik | Keputusan | Alasan |
|---|---|---|
| Penyimpanan file | Tidak disimpan. JSON dibuat saat diminta dan langsung diunduh dalam respons yang sama (`Content-Disposition: attachment`, `Cache-Control: no-store`). | Tanpa storage baru; tidak ada file yang perlu dibersihkan, jadi AC "file kedaluwarsa dibersihkan" terpenuhi secara desain. "Terbatas waktu" = hanya respons re-auth itu sendiri. |
| Re-authentication | Akun email: password dimasukkan ulang dan diverifikasi ke GoTrue tanpa mengganti sesi. Akun Google saja: login Google terakhir ≤ 10 menit, jika tidak diminta masuk ulang dengan Google lalu kembali ke Profil. | SRS §11: re-auth untuk ekspor. |
| Isi ekspor | Profil, email akun, semua catatan gula darah (termasuk yang ditandai salah, alasan koreksi, tautan pengganti, nilai asli dan mg/dL, waktu ukur/catat), bukti persetujuan, persetujuan cookie, permintaan penghapusan, riwayat ekspor. Tabel jadwal/kontak/notifikasi ikut bila sudah berisi (fitur Sprint 3). | Hak akses dan portabilitas data pribadi (UU PDP); tidak menyertakan data admin atau data pengguna lain. |
| Format | Satu file JSON `glubee-data-YYYY-MM-DD.json` dengan `schemaVersion`, `generatedAt`, `timezone`. | Sesuai AC. CSV bisa ditambah nanti bila diminta. |
| Jejak | Setiap ekspor mencatat baris `data_exports` (state `expired`, `expires_at = now()`, `object_ref` kosong) dalam transaksi yang sama. | Bukti pemenuhan hak, tanpa menyimpan isi. |
| Batas | Rate limit `account.export` 5/menit per akun. | Mencegah tebak password dan beban DB. |
| Akun dinonaktifkan admin | Ekspor **diizinkan** dari halaman Status akun; hanya akun `deleted` yang ditolak (migration `20261002000200`). | Keputusan pemilik produk 1 Okt 2026: mengikuti hak akses subjek data UU PDP. |

## Dampak ke aplikasi

- **Database**: 1 migration baru (RPC `export_my_data`, route rate limit). Tidak ada perubahan tabel. Production: migration dijalankan manual di VPS seperti migration admin.
- **API**: route baru `POST /api/account/export`; `/auth/callback` menerima `next=/profile` untuk kembali setelah re-login Google.
- **UI**: bagian "Privasi & hak Anda" di Profil mendapat tombol "Unduh data saya" + dialog re-auth; teks "dijadwalkan pada Sprint 3" diperbarui. Banner halaman legal menghapus "ekspor data" dari daftar fitur yang belum tersedia.
- **Keamanan**: endpoint baru yang mengeluarkan data kesehatan dalam satu respons; dilindungi sesi + re-auth + rate limit + origin check (proxy). Tidak ada URL publik/permanen.
- **Infra**: tidak ada storage, cron, atau perubahan nginx.
- **Tes**: pgTAP (pemilik saja, grace period boleh, suspended/anon ditolak, jejak tercatat), unit (keputusan re-auth, nama file), Playwright (password salah ditolak, unduhan berisi catatan sendiri saja).
- **Dokumen**: SRS §6/§10 (tanpa object storage), checkpoint ini, ClickUp.
