# Checkpoint GLB-020: Push, pengingat dashboard, email fallback

Task: [GLB-020](https://app.clickup.com/t/86eyvadwt) · Jadwal 12-13 Oktober 2026 (dikerjakan 9 Okt) · Kebutuhan: FR-REMINDER-001, SRS §9

## Acceptance criteria (ClickUp)

1. Push hanya untuk izin/subscription valid; email fallback diuji saat push tidak tersedia atau ditolak.
2. Dashboard tetap menampilkan pengingat; error/subscription invalid ditangani; uji provider memakai lingkungan dan penerima uji.

## Keputusan desain

| Topik | Keputusan | Alasan |
|---|---|---|
| Kanal | Satu pengingat per occurrence. Producer memilih `push` bila ada subscription aktif, selain itu `email`. | FR: satu job per kanal yang berlaku, tanpa duplikasi logis; email tidak dikirim ganda ke pengguna yang menerima push. |
| Fallback | Push `no_subscription` saat klaim, gagal permanen (400/403/404/410 semua perangkat), atau 3 percobaan habis → job email `reminder:email:<occurrence>`. Retry push (429/5xx/jaringan) tidak memicu fallback. | FR: fallback saat push tidak tersedia/ditolak. |
| Multi-perangkat | Satu job push dikirim ke semua subscription aktif (maks. 10); cukup satu berhasil. 404/410 → subscription dinonaktifkan. | SRS: revoke saat gagal permanen. |
| Penyimpanan | Subscription JSON dienkripsi AES-256-GCM di aplikasi, endpoint di-HMAC untuk dedupe. Kunci `DATA_ENCRYPTION_KEY` per lingkungan; dipakai juga untuk email kontak (GLB-021). | SRS §11: enkripsi field kontak/push di aplikasi. |
| Kunci VAPID | Dibaca runtime (`VAPID_PUBLIC_KEY`, bukan `NEXT_PUBLIC_*`) dan dikirim ke klien lewat `GET /api/push-subscriptions`. | Satu image untuk staging dan production. |
| Service worker | `public/sw.js` hanya `push` + `notificationclick`, tanpa cache. | Data kesehatan tidak boleh tersimpan di cache browser. |
| Dashboard | Kartu "Jadwal hari ini" dari `/api/schedules` (bukan antrean). | Selalu tersedia, tidak bergantung pada kanal lain. |
| Aktivasi | `REMINDER_PUSH_ENABLED=false` sampai uji kolektif di staging. | Keputusan pengguna 9 Okt. |
